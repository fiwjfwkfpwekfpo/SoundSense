# SoundSense — функционал (ТЗ)

Личный музыкальный плеер для ПК (Linux, Windows) и Android. Простой, лёгкий, стабильный.

## 0. Принципы

- **Минимум.** Только то, чем реально пользуешься. Никаких визуализаторов и редакторов. Плагины — позже, отдельным этапом (раздел 14).
- **Не ломается.** Всё, что зависит от чужих сервисов, вынесено в заменяемые части (yt-dlp, источники). У каждого действия есть запасной путь.
- **Всё настраивается.** Каждая настройка описана в одной схеме, экран настроек строится по ней сам.
- **Темы на токенах.** Ни одного цвета в коде, всё через переменные. Проверка в `npm run lint`.
- **Локально в первую очередь.** Работает без интернета (то, что скачано). Синхронизация не зависит от своего сервера: облако пользователя и напрямую между устройствами. Свой сервер используется только для обновлений и как необязательное ускорение.
- **Без телеметрии и рекламы.**

## 1. Платформы и стек

| Часть | Чем |
|---|---|
| Общее ядро (источники, библиотека, очередь, синхронизация) | TypeScript |
| Интерфейс (один на ПК и телефон) | Svelte + Vite |
| ПК | Electron: Linux и Windows. Сборки: AppImage (+ PKGBUILD для AUR), Windows — установщик и portable (собираются на Linux через electron-builder) |
| Android | Capacitor (тот же интерфейс) + нативные части на Kotlin |
| Получение потоков | yt-dlp: на ПК бинарник, на Android библиотека youtubedl-android |
| Хранилище данных | IndexedDB (одинаково на ПК и телефоне) |
| Синхронизация | облако пользователя (Яндекс Диск, Google Drive, WebDAV) + напрямую (WebRTC) |

Код хранится локально в `~/Projects/SoundSense`, удалённого репо нет. APK собирается на ПК.

## 2. Источники музыки

Все источники работают по одному интерфейсу: поиск, данные трека, поток, импорт. Новый источник добавляется одним модулем.

### SoundCloud
- Поиск треков, исполнителей, плейлистов.
- Воспроизведение через API (ключ client_id находится и обновляется сам), запасной путь — yt-dlp.
- Импорт по ссылке: лайки (`/likes`), плейлисты (`/sets/`), треки исполнителя. Большие списки (2000+) грузятся быстро, пачками.
- Готовая волна (`waveform_url`).
- Превью (30 с, треки Go+) помечаются и не играют вместо полного трека.

### YouTube Music
- Поиск (треки, альбомы, исполнители), воспроизведение через yt-dlp.
- Импорт плейлистов по ссылке.
- Аудио без перекодирования (opus/m4a), лучшее доступное качество.

### Яндекс Музыка
- Вход своим аккаунтом (OAuth Яндекса внутри приложения). Токен хранится в защищённом хранилище системы.
- Поиск, воспроизведение, импорт «Мне нравится» и плейлистов.
- Тексты песен из Яндекса (если есть).

### Локальные файлы
- Выбор папок, автосканирование, чтение тегов (название, исполнитель, альбом, обложка).
- FLAC, MP3, OGG/Opus, M4A, WAV.
- Файлы никогда не меняются плеером.

### Один трек, несколько источников
- Трек в библиотеке — это одна запись со списком источников (`sources: [sc, yt, ya, local]`).
- Если источник недоступен (удалили трек, блок региона), плеер сам ищет тот же трек в других источниках (по названию, исполнителю и длительности) и предлагает замену.
- Дубликаты при импорте склеиваются.

## 3. Библиотека

- **«Мне нравится»** — одна общая для всех источников. Лайк ставится в плеере. Обратно в SC и Яндекс не отправляется (позже можно, отдельной настройкой).
- **Плейлисты:** создать, переименовать, удалить, обложка (своя или из треков), сортировка (ручная, по дате добавления, названию, исполнителю, длительности), поиск внутри.
- **История:** последние N прослушиваний (N настраивается).
- **Скачанное:** отдельный раздел.
- **Локальные файлы:** отдельный раздел.
- **Импорт:** по ссылке (SC, YT Music, Яндекс), из аккаунта Яндекса, из папки. Повторный импорт той же ссылки добавляет только новые треки.
- **Экспорт:** плейлист в JSON и M3U, полный бэкап библиотеки одним файлом.
- **Скрыть исполнителя или трек** (не показывать в поиске и рекомендациях).

## 4. Воспроизведение

- Очередь: «играть следующим», «в конец очереди», перетаскивание, удаление, очистка.
- Перемешивание, повтор (выкл / вся очередь / один трек).
- **Плавный переход между треками** (как в Яндекс Музыке и Spotify): последние N секунд текущего трека и первые N секунд следующего звучат одновременно, громкость одного плавно уходит, другого — нарастает (равномощная кривая). N настраивается 0–12 с (0 = выкл), по умолчанию 3 с.
  - Тишина в конце и начале трека не считается: момент перехода берётся по волне (там, где звук реально кончается/начинается).
  - При ручном переключении (вперёд/назад, выбор трека) — не склейка, а короткое затухание ~0.3 с.
  - Подряд идущие треки одного альбома — без склейки (gapless), отключается настройкой.
  - Следующий трек заранее буферизуется, чтобы склейка не прерывалась.
  - Анимации смены трека (обложка, название, волна) синхронизированы со склейкой и проходят во время неё.
- Выравнивание громкости между треками (вкл/выкл).
- Продолжение с того же места после перезапуска.
- Фоновое воспроизведение.
- **ПК:** медиаклавиши, MPRIS (управление из Quickshell/playerctl), сворачивание в трей (настраивается).
- **Android:** уведомление с кнопками, экран блокировки, наушники и Bluetooth-кнопки, пауза при отключении наушников и при звонке.
- Горячие клавиши на ПК, все переназначаются.

## 5. Звук

- **Скорость** 0.5–2.0×, отдельно или вместе с тоном.
- **Тон** ±12 полутонов.
- **Пресеты:** Slowed + Reverb, Nightcore, Обычный, свои.
- **Реверб:** размер комнаты, смесь.
- **Эквалайзер:** 10 полос (32 Гц – 16 кГц), пресеты (Bass Boost, Vocal, Flat и др.) и свои.
- Эффекты действуют глобально, по желанию можно закрепить настройки за конкретным треком.
- Обрезка начала и конца трека (пропуск тишины или интро) — сохраняется для трека.

## 6. Волна вместо прогресс-бара

- **SoundCloud:** готовая волна с их сервера.
- **Всё остальное:** считается на устройстве (декодирование → ~1000 кусочков → громкость каждого). На наших серверах ничего не считается.
- **Кэш волн отдельно от кэша треков:** удалил трек из кэша или скачанного — волна остаётся. Свой лимит и своя очистка в настройках.
- Волны синхронизируются между устройствами (по паре килобайт).
- Тап или перетаскивание по волне — перемотка. Сыгранная часть и остаток разного цвета, время.
- **Можно выключить:** тогда обычная полоса прогресса.
- Пока волна считается, показывается обычная полоса.
- **Расчёт потоковый:** декодер отдаёт аудио блоками, каждый блок сразу раскладывается по столбикам (пик/RMS) и выбрасывается. Полный PCM в памяти не хранится, память постоянная при любой длине трека, без ресемплинга.
  - ПК: `ffmpeg -ac 1 -f f32le -` в поток, агрегация по кускам в Node.
  - Android: `MediaExtractor` + `MediaCodec` (нативный плагин на Kotlin).
  - Браузер (только для разработки UI): `decodeAudioData`.
- Считается в фоне (Worker / отдельный поток), волна заполняется слева направо по мере декодирования. Считаем только текущий и следующий трек; на телефоне не при низком заряде.
- Сохраняется как `Uint8` (~1000 байт на трек), ключ: источник + id трека + версия алгоритма (при смене формулы — пересчёт).

## 7. Тексты песен

- Источники: lrclib (синхронные и обычные), Яндекс (если вход выполнен). Порядок источников настраивается.
- Синхронный текст: подсветка текущей строки, автопрокрутка, тап по строке — перемотка.
- Сдвиг тайминга вручную (сохраняется для трека).
- Свой текст: вставить вручную или загрузить `.lrc`.
- Подбор текста по треку с проверкой длительности и исполнителя.
- Кэш текстов, синхронизация правок.

## 8. Офлайн

- Скачать трек, плейлист или все лайки.
- Формат: оригинал без перекодирования (opus/m4a/mp3) или перекодировать в выбранный.
- Где хранить: на ПК — папка (настраивается), на Android — память приложения или SD.
- Лимит места, автоудаление самых старых (вкл/выкл).
- Очередь загрузок с прогрессом, отменой и повтором; при обрыве сети докачивается.
- Скачанный трек помечен в списках и играет без интернета.
- **Кэш прослушанного** (автоматический, свой лимит) — отдельно от **скачанного** (вручную).
- Режим «только скачанное».
- На Android: качать только по Wi-Fi (настройка).

## 9. Синхронизация ПК ↔ телефон

Что синхронизируется (каждое отдельно включается): лайки, плейлисты, история; настройки (кроме привязанных к устройству); тема; волны, правки текстов, обрезки; «продолжить на другом устройстве».

Своего сервера нет. Два канала работают **одновременно** и друг другу не мешают:

- **Облако пользователя** — основной, работает всегда. Скрытая папка приложения на Яндекс Диске (по умолчанию), в Google Drive (`appDataFolder`) или на любом WebDAV (например, Nextcloud). Вход через OAuth провайдера (WebDAV — логин и пароль приложения). Каждое устройство пишет **только свой** файл `device-<id>.json` и читает файлы остальных — конфликтов записи нет. Проверка обновлений при запуске, при возврате в приложение и по таймеру (интервал настраивается). Устройствам не нужно быть онлайн одновременно.
- **Напрямую (WebRTC)** — когда оба устройства открыты: изменения приходят мгновенно, работает «продолжить на другом устройстве». Связь устанавливается через публичный сервер-посредник (только знакомит устройства, данных не видит).

- **Связка:** код из 8 символов или QR, один раз. Код передаёт ключ шифрования группы и какое облако выбрано; вход в это облако на каждом устройстве свой (токены между устройствами не передаются).
- **Слияние:** у каждого элемента время изменения, побеждает более новое, удаления распространяются (логика Muriel). Одно изменение может прийти обоими каналами — это безопасно, повтор ничего не меняет.
- **Офлайн-изменения** копятся и уходят при появлении сети.
- **Шифрование:** файлы в облаке зашифрованы ключом группы на устройстве. Яндекс и Google видят только зашифрованные данные.
- **Временные обменники** (temp.sh, file.io и т.п.) не используются: файлы удаляются через несколько дней, нет постоянного адреса.
- **Публичные плейлисты** (на будущее): через публичную ссылку на файл в облаке пользователя.

## 10. Интерфейс

Экраны: Главная, Поиск, Библиотека (лайки, плейлисты, скачанное, локальные, история), Плейлист/исполнитель/альбом, Плеер на весь экран, Очередь, Настройки. Мини-плеер внизу. Языки: русский, английский.

**Первый запуск:** два экрана, оба можно пропустить: 1) выбор цвета приложения — сетка палитр с живым превью, по умолчанию «Обложка»; 2) импорт музыки (SoundCloud, Яндекс, Spotify, YouTube Music, папка).

**Анимации:** образец — `docs/reference/animations.html` (стопка обложек, стекание, цвет растекается от обложки, табло, расшифровка названия, перетекание волны, перелёт элементов, кнопка → мини-плеер, жидкий индикатор вкладок, капля из панели, круг из точки, глубина, каскад, ЭЛТ, play↔pause, лайк с искрами). Особое внимание — смене трека и волне.

## 11. Оформление и настройки

Оформление — три **независимые** оси, каждая со своими пресетами и своим файлом пакета. Любая комбинация допустима (например, стиль «Ретро» + цвета «Золото»). Подробности — `docs/APPEARANCE.md`.

- **Стиль** (только форма: радиусы, шрифты, рамки, тени, blur, плотность): Стандарт, Ретро, Плоский, свой.
- **Цвета** (только палитра, роли как в Quickshell). **По умолчанию — «Обложка»** (цвета из текущего трека, плавно меняются при смене трека). Цветные пресеты — из удачных тем HyprTheme пользователя, под своими названиями: Аметист (PURPLE), Серебро (stardust), Лайм (gamesense), Золото (urushi). Плюс Монохром, AMOLED, Высокий контраст, свой. Стиль «Ретро» подсказывает «Лайм».
- **Анимации:** группы (общие, плеер, название трека, обложка, текст песни, волна). Пресеты: Плавный, Пружинный, Ретро, Минимум, Выкл. Общий пресет + любой группе можно взять пресет из другого. Множитель скорости, учёт «уменьшить движение».
- Стиль может подсказывать цвета и анимации (Ретро → Лайм + ретро-анимации), если пользователь не выбирал их вручную; отключается настройкой.
- Пакеты частичные, проверяются по одной схеме; битый пакет не применяется — остаётся прошлый. Производные цвета (градиенты, тени, волна) считаются из палитры.
- `npm run lint` падает, если цвет захардкожен вне пакетов цветов (включая градиенты и тени).
- **Настройки:** одна схема (ключ, тип, значение по умолчанию, синхронизировать или нет), экран строится по ней. Экспорт, импорт, сброс по разделам.

## 12. Надёжность

**Обновления приложения:** подписанные (Ed25519 + SHA-256 + проверка сертификата APK), из ветки `releases` репозитория на GitHub — подробности в `docs/RELEASES.md`. Ключи подписи хранятся только у разработчика, обязательна резервная копия. yt-dlp обновляется сам; цепочка запасных путей (API → yt-dlp → другой источник); повторы при сетевых ошибках; понятные ошибки; атомарная запись и автобэкап; тесты ядра; журнал ошибок.

## 13. Приватность

Никакой телеметрии. Токены в защищённом хранилище системы. Облачные провайдеры видят только зашифрованные данные синхронизации.

## 14. Не делаем

Discord-статус в ядре (можно будет плагином), визуализаторы, редактор CSS, баннеры и видеофоны, mesh-градиенты, TV/караоке-режим, аудиоредактор (кроме обрезки), Spotify и Apple Music как источники воспроизведения (из Spotify — только импорт лайков и плейлистов из архива выгрузки). Рекомендации и «Моя волна» — позже (в UI пока заглушки).

**Плагины:** API и каталог описаны в `docs/PLUGINS.md` (JS-плагины в песочнице Web Worker, один пакет для ПК и Android, разрешения, декларативный UI, свои источники/тексты/импорт). Ядро построено вокруг шины событий, реестров поставщиков и слотов UI — встроенные источники регистрируются так же, как плагины.

## 15. Где хранятся файлы

Три категории, у каждой одна папка на платформе:

- **Настройки** — настройки и темы. Маленькие, их можно хранить в dotfiles.
- **Данные** — библиотека, волны, скачанные треки, логи, yt-dlp. Бэкап одной папки = ничего не потеряно. Волны лежат здесь, а не в кэше, чтобы пережить очистку кэша.
- **Кэш** — прослушанные треки, обложки, тексты, профиль Chromium. Удаляется в любой момент без последствий.

| | Linux | Windows | Android |
|---|---|---|---|
| Настройки | `~/.config/soundsense/` | `%APPDATA%\SoundSense\` | `files/config/` (внутренняя память приложения) |
| Данные | `~/.local/share/soundsense/` | `%LOCALAPPDATA%\SoundSense\Data\` | `files/data/` (внутренняя память приложения) |
| Скачанное | `<данные>/downloads/` | `<данные>\downloads\` | `Android/data/<appId>/files/Music/` (можно на SD) |
| Кэш | `~/.cache/soundsense/` | `%LOCALAPPDATA%\SoundSense\Cache\` | `cacheDir` (система может чистить сама) |
| Токены аккаунтов | keyring (libsecret) | DPAPI | Android Keystore |

Правила:
- На Linux уважаются переменные `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`.
- Chromium держит дисковый кэш внутри `userData`, а Electron игнорирует `app.setPath('cache')` и `--disk-cache-dir`. Поэтому на Linux папки кэша Chromium в `<данные>/chromium/` — символические ссылки в `<кэш>/chromium/` (`desktop/caches.mjs`); в папке данных остаётся только то, что стоит бэкапить.
- AppImage при запуске сам ставит запись меню и иконки в `$XDG_DATA_HOME` (`desktop/integration.mjs`; `--remove-integration` убирает, `SS_NO_INTEGRATION=1` отключает; записи чужих менеджеров AppImage не трогаются). Иконки: `assets/branding/icons/NxN.png`, размеры 16–512.
- Electron по умолчанию складывает всё в одну папку настроек, поэтому при старте пути (`userData`, кэш, логи) переопределяются явно, до создания окна.
- Папку скачанного можно сменить в настройках (например, на `~/Music/SoundSense`, чтобы файлы видели другие плееры). На Android есть опция «показывать в других плеерах» (MediaStore → `Music/SoundSense`).
- Если keyring недоступен (на Hyprland его может не быть), приложение не сохраняет токен открытым текстом, а предупреждает и просит войти заново.
- Android Auto Backup: в бэкап идут настройки и библиотека, кэш и скачанное исключены.
- Удаление приложения на Android удаляет всё, включая скачанное (кроме того, что было в MediaStore).
